# Agent 用例库 · 中文版

别人用 AI Agent 真干成了什么 — [agentusecases.ai](https://agentusecases.ai/) 的中文整理。

在线地址：https://chenqinhong63.github.io/agent-use-cases-zh/

## 这是什么

原站是 Alex Finn 运营的免费 AI Agent 实战案例库，每天从 X、Reddit、Hacker News 等公开平台扫描新增案例。本站把它的案例翻译成中文，做成可搜索、可筛选的静态网站：

- 3336 条案例：2263 条翻译案例（2026-11-21 全量搬运，后续每天自动同步新增）+ 12 条中文实测案例（小红书 4、抖音 1、B站 4、微博 3）+ 1061 条批量中文案例（见下节）
- 11 个分类：软件与运维、运营与效率、生活与家庭、增长与营销、金钱账单与权益、研究与分析、购物与比价、创意与内容、出行与旅行、游戏、科学
- 支持中英文搜索、按分类筛选、按 Agent 筛选、每页 24 条、随机来一条
- 每条点开有中文简介、可一键复制的中文提示词，以及链回原文页的“原文 ↗”链接
- 中文实测案例 12 条排在最前，其次是 1061 条批量中文案例，都带来源平台徽标
- 卡片上的 Agent 标签可点，直达各 Agent 官网（见下节）

## 中文原创投稿

翻译之外，本站收中文原创案例，目标是变成中文首发源：别人用 Agent 真干成的事，中文读者先在这里看到。

- 投稿入口：[提交原创案例](https://github.com/chenqinhong63/agent-use-cases-zh/issues/new?template=submit-use-case.yml)（GitHub Issue 模板，会问标题、用的 Agent、做了什么、结果、提示词、可验证的链接、署名）
- 审核流程：只收真实做过的事，不收编造和搬运；维护者审核通过后，把案例加入 `data/cases-original.json`，上站时署投稿人的名
- 每日自动更新只同步翻译案例，原创靠人工审核入库，不走自动流程
- 站长原创种子 10 条已按站长要求下架（文件已从仓库删除，本地留有存档，当前页面不加载）；投稿功能收的是读者自己的真实案例，不是站长本人的项目——以后没有站长明确要求，不许再发站长自己的项目上站。审核通过的读者投稿先入库，待站长确认后随后续版本恢复展示。

## Agent 官网链接与中文实测案例

- Agent 标签链官网：`data/agent-links.json` 存 47 个 Agent 的官网映射（43 个有链接，4 个是 null），卡片上的 Agent 标签有链接的点开即跳官网（新窗口），没链接的显示为纯文字。Custom agent 是通用类别名、不是具体产品，Claude computer use 是 Anthropic API 的开发者工具集、无独立产品首页，dsh-graph 是 DeepSeek Harness 的子项目、DeepSeek-V4.1-Flash 是模型名而非产品，所以这四者没有官网链接、只显示文字。批量案例里出现 ≥5 次的新 Agent 已补进映射：Coze（扣子中国版官网）、Dify、Trae（中国版官网）、AutoGLM（THUDM 官方仓库）、Grok、LangGraph、Eino（CloudWeGo 官方文档）；出现 <5 次的新 Agent 未入映射，页面上显示为纯文字。链接取不到时自动降级为纯文字标签，页面不会白屏。
- 小红书 4 条：`data/cases-xiaohongshu.json`，是经核实的作者文章整理而来（作者：南墙、AI设计师阿东、饼干哥哥、鲲鹏AI探索局），不是直接扒小红书站内笔记。数据里存的 url 是作者文章的转载/发布页链接（如掘金、作者博客），不是小红书站内笔记直连——公开渠道拿不到小红书笔记直连链接。

- 来源分布前五名：V2EX 308、B站 223、虎嗅 152、掘金 87、微信公众号 63；其余来自少数派、CSDN、知乎、头条、GitHub 等 20 多个中文渠道

## 每张卡片恢复“原文 ↗”链接

每张卡片点开后，详情区底部除“复制提示词”外恢复了一个“原文 ↗”链接（新窗口打开），直接用每条数据的 `url` 字段，不改写：翻译案例链到 agentusecases.ai 的详情页，小红书 4 条链到作者文章页。点“原文 ↗”不会触发卡片展开/收起。

## 本地预览

```bash
python -m http.server
```

然后打开 http://localhost:8000/ 。不要直接双击 `index.html` 打开，浏览器会拦 `fetch('data/cases.json')`。

## 每日自动更新

`.github/workflows/daily.yml` 每天北京时间 09:00（UTC 01:00）自动运行，也可手动触发（Actions → 每日更新案例 → Run workflow）：

1. 跑 `python scripts/update.py`：读原站 sitemap，找出本地没有的新案例，逐个抓详情页解析；
2. 若 `data/cases.json` 有变化，自动 commit 并 push，GitHub Pages 随后自动重新发布。

翻译用的 Key 只从仓库 Secrets 读 `DASHSCOPE_API_KEY`，绝不写进仓库文件。没配 Key 时新增条目会先以英文原文入库并标“待翻译”；已入库的待翻译条目不会在后续运行中自动重翻，如需补翻需手动处理。

手动跑一次（只看会新增哪些，不写文件、不调翻译接口）：

```bash
python scripts/update.py --dry-run
```

## 翻译说明

- 标题与简介是原站案例的中文翻译，保留了原文的关键数字、结果与缺点，没有夸大。
- 提示词是按案例改写的中文提示词模板（带 `[ ]` 占位符），不是原站提示词原文；原站提示词原文存在每条数据的 `prompt_en` 字段里备查（仅每日更新的新增条目有，老的 2263 条当时只取了分类页，没有逐条抓详情页的提示词原文）。
- 部分案例是美国场景（如报税、Comcast、AT&T、Medicare），翻译时保留了原场景，没有改成中国场景。
